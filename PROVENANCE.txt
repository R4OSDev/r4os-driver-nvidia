0.79.10 offline RM/NVKMS source build, 10.09.2026:
Tools/Rm/Sources.json records the digest of 3156 original source/header/build
and license files (96017025 bytes), checked against the archived per-file
catalog and the original 18701915-byte GitHub source archive. Archive SHA-256:
363b011b1692401529b492f7bdfbf115412820462261dc2b129aa1d5c94b37c9.
Its source revision must match src/firmware-lock.json; there is no alternative
RM version selected by a host flag. The explicit build-rm step copies and
verifies a private snapshot, then builds the original srcs.mk lists with
component-specific flags and upstream RM export/linker inputs.
No original sources or compiled RM objects are added to this public repo or
to NVIDIA.R4D. The private build tree retains COPYING and every file notice.

The version-only guard adaptation in src/common/inc/nvUnixVersion.h adds
NV_R4OS without modifying original references or defining NV_LINUX/NV_BSD.
The generated overlay preserves the original notice. Compiler target flags,
deterministic ID strings, output inspection and orchestration are R4OS work.
Primary OS boundary references remain the pinned os-interface.h/nv.h and
nvidia-modeset-os-interface.h. Linux crypto bindings are visible in
kernel-open/nvidia/libspdm_internal_crypt_lib.c, libspdm_sha.c and related
libspdm_*.c; those files are references, not linked OS implementations.
This source-only build does not establish a full link, functioning OS adapter,
GSP authentication or hardware admission. Its outputs list unresolved symbols
and preserve the distinction between partial-object and loaded relocations.

The source-only build now also embeds the eight original NVKMS shader files
from src/nvidia-modeset/src/shaders/g_*_shaders. Their source revision and
input hashes remain covered by Tools/Rm/Sources.json. The source Makefile's
COMPRESS_SHADERS list selects the families. Its XZ -ce -C none flags determine
the format; an explicit single thread and removed XZ option environment avoid
host-dependent defaults. Generated g_*_shader_info.h ProgramHeapSize fields
must match the original file extents. No shader opcode or metadata is edited.

Verification compiles the original src/common/unix/xzminidec/src/
xz_crc32.c, xz_dec_lzma2.c and xz_dec_stream.c with NVKMS's decoder defines
and src/common/unix/nvidia-3d/include/nv_xz_mem_hooks.h. The original
nvidia-3d/interface/nvidia-3d-imports.h declares the host memory hooks;
the R4OS verifier implements them with actual host malloc/free/memory calls.
The comparison to nvidia-3d/src/nvidia-3d-fermi.c preserves XZ_SINGLE and
checks full input/output consumption and exact decoded bytes additionally.
The same release's nvidia-3d-init.c defines the sixteen expected boundary
symbols. The resulting readonly objects are partial-link inputs only.

0.79.10 CPU memory adapter subset, 10.09.2026:
src/rm/os_memory.c, nvkms_memory.c and memory.h are original R4OS code.
The pinned os-interface.h and nvidia-modeset-os-interface.h provide the actual
prototypes; kernel-open/nvidia/os-interface.c and
kernel-open/nvidia-modeset/nvidia-modeset-linux.c are behavioral references,
not copied Linux implementation code. The original RM gcc_helper.c wraps
memcpy/memset through os_mem_copy/os_mem_set, so the R4OS integer-register
implementations avoid calling those symbols recursively. No register map,
MMIO, DMA, GPU execution or synchronization backend is implemented here.
Tests/RmMemory.c uses host allocation and guard pages only in the host checker.
Two private target heap imports remain deliberately unresolved. The original
headers and licenses stay in the verified private source snapshot; no third-
party source is added to this public repository by the adapter implementation.

0.79.10 resident CPU provider, 10.09.2026:
src/rm_heap.zig and runtime_probe.zig are original R4OS code. The provider
implements the two private C hook signatures through the real DriverApi30
resident heap. Its 16-byte prefix stores only the allocation identity and a
corruption marker; it does not reproduce a Linux allocator or OS interface.
The explicit R4D CPU diagnostic executes real init/work/close calls. The
separate RM/NVKMS partial objects are not yet linked with this provider and
continue to list those imports; their earlier source-build evidence remains
historical and unchanged. No new third-party material is introduced.
